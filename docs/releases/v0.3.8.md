# wow 0.3.8

Three things for a chat thread: find text in the conversation and take it with you, give the
thread its own working copy, and see what tools the session has.

Built and reviewed by agents, run against mock agents and mock hosts only. Read "Known gaps".

## Changes

### Find in the conversation and copy it

- **Ctrl+F finds text in the thread:** in messages, tool rows and output, with a count and F3 and
  Shift+F3 for the next and the previous match. A match inside a closed row, a group, reasoning
  or long output opens it.
- **"Copy conversation as Markdown" and "Save conversation…"** give the thread as Markdown: the
  messages, and one line per tool call without its output. Reasoning is left out unless
  `chat.exportReasoning` is on.
- Neither is offered in the Assistant view.

### A thread in its own working copy

- **A chat thread in a Git project can have its own working copy,** a git worktree on a new
  branch, so two threads do not edit the same files. Choose it when you start the thread, or set
  `chat.ownWorkingCopy` for the project. The thread shows its branch.
- The copy is made before the first turn goes out. If git cannot make it, the turn fails with
  git's reason; the thread never falls back to the project folder.
- **"Remove working copy"** says what is in it that would be lost and asks first. It is refused
  if the copy changed after the dialog was shown. Marking the thread done removes the copy only
  when nothing would be lost.
- **wow never deletes a branch.** The branch and its commits stay when the copy is removed.

### What the session can use

- **A Tools tab in the thread's panel** lists the MCP servers with their state and error, and the
  tools, skills, slash commands and subagents Claude Code reports for the session. A chip in the
  header shows when a server failed. It is read-only.
- wow shows only what the provider reported and starts nothing to fill the tab. Arguments,
  environment values and the parts of an address that can hold a key are hidden.

### Fixed since 0.3.7

- A message handed to the running turn waits for the turn's start, as a stop does.

## Known gaps

- Nothing in this release has been run against a real Claude Code or Codex, a real host, or on
  Windows outside CI. What Claude Code reports about its tools and MCP servers is read from the
  SDK's types, not seen from the real program.
- On Codex the Tools tab shows only the instruction files and the servers seen in the thread's
  own tool calls; its protocol has no list to ask for.
- A try at making a working copy that git stopped half-way can leave a `wow/…` branch in the
  repository. The next try uses it if nothing moved it; wow does not delete it. With Git's reflog
  switched off the next try fails with git's reason instead.
- Counting what a working copy holds reads every ignored file, also in large folders such as
  `node_modules`. How long that takes on Windows is not measured.
- A file edited again without changing its Git status between the Remove dialog and the yes is
  not noticed.
- A value shorter than four characters is never hidden in the Tools tab.
- Files are not put back when you edit a message, and a thread's changes cannot be committed
  from wow yet. Both are planned next.
