# wow 0.3.9

Put a thread's files back to how they were when you sent a message.

Built and reviewed by agents, run against mock agents and mock hosts only. Read "Known gaps".

## Changes

### Restore files

- **"Restore files to here"** on one of your messages (its button, **R**, or the palette) puts
  the thread's folder back to how it was when that message was sent: changed files get their
  content back, new files are deleted, deleted files come back. The conversation stays as it
  is, so it works on Codex too.
- **A confirm lists what is written and deleted.** Files that changed outside the thread since
  its last turn come first, and the button then reads "Restore anyway". When wow has no record
  of how the thread left the folder, it says so and treats every touched file as possibly yours.
- **Undo** is offered until the next message or the next restore, and gives back exactly what
  was there.
- **Editing a message can take the files with it.** Above the box you pick "Conversation only"
  or "Conversation and files"; `chat.editRestoresFiles` picks which comes first.
- **A restore never touches** commits, branches, staged changes or ignored files, and never
  writes outside the thread's folder. Neither the assistant nor a workflow step can start one.
- **Some files are left alone and named:** a file the thread did not leave there (for example
  one Git lists only since `.gitignore` changed) and a file over `chat.snapshotMaxFileBytes`,
  which wow holds no copy of.

### Where the snapshots are

- wow keeps the snapshots in its own folder (`snapshots/`), never in your repository, for
  `chat.snapshotKeepDays` days.
- **A snapshot holds the contents of every file Git does not ignore, unencrypted.** A file with
  a secret in it that is not in `.gitignore` is copied there too. `chat.snapshots` turns
  snapshots off for a project. The assistant has no tool that reads wow's folder.

## Known gaps

- Nothing in this release has been run against a real Claude Code or Codex, a real host, or on
  Windows outside CI. Restore on Windows (CRLF files, a file an editor holds locked, a path with
  spaces) is covered by tests in CI only.
- The first snapshot of a large folder delays the first turn. How long on Windows is not
  measured; `chat.snapshotMaxFiles` and `chat.snapshotTimeoutMs` bound it.
- Restore is not offered for a folder outside Git, a step's thread, or messages sent before
  this version.
- On Windows, one folder is still held for a moment at the end of an e2e run in CI; the cause
  is not found.
- A thread's changes cannot be committed from wow yet. That is planned next.
