# wow 0.3.2

The first part of making chat in wow as good a place to work with an agent as Claude Code and
Codex: a model bar at the composer, drafts and queued messages that are never lost, tool rows
that read like a terminal, and a thread list that tells you what needs you.

Built and reviewed by agents, run against mock agents only. Read "Known gaps".

## Changes

### Model, effort and mode at the composer

- **A bar at the composer** shows the thread's model, effort and permission mode. Ctrl+Shift+M
  picks the model, Ctrl+Shift+E the effort, and Shift+Tab steps through the permission modes.
  Each has a palette command. Escape leaves the composer.
- The lists show what the provider offers and mark its default. A new thread starts on the
  provider's default model and that model's default effort.
- The assistant has the same bar for its own provider, model and effort.

### The composer keeps what you wrote

- **A draft stays with its thread** when you switch threads and after a restart.
- **A message sent while a turn runs is queued** and shown as a row you can cancel. On Claude Code
  it can be handed to the running turn; otherwise it is sent when the turn ends.
- **Commands in the composer:** `/` lists commands beside skills, among them `/clear` and
  `/rename`. Which ones show depends on what the provider offers.

### Reading what the agent does

- **Tool rows:** a command reads `$ command` with its folder when that differs, and its exit code
  or "failed" with the time it took. Reads, searches and web calls are one line. An MCP call
  shows its server and tool with its arguments. A group of calls gets a summary when closed.
- **The task list stays in view,** pinned above the composer; Ctrl+T shows or hides it.
- **Copy buttons** on messages, code blocks and tool output, with palette commands. A failed copy
  says so.
- A turn you stopped says "Stopped by you" with the time.

### Threads

- **A chat thread that needs you, or finishes while you are elsewhere, notifies you.**
- **The thread list** can be filtered by text and by project, and searches message text. A thread
  can be renamed (F2), archived and marked unread; unread threads are bold, and a key jumps to the
  next one. An archived thread comes back when a turn starts or a request arrives in it.

## Known gaps

- Nothing in this release has been run against a real Claude Code or Codex, or on Windows outside
  CI. `docs/windows-smoke.md` has new lines for what the tool rows and the model bar rely on.
- Claude Code gives no exit code for a command; a failed command reads "failed" with the time the
  server measured.
- Escape in a workflow step's composer leaves the composer first, so the side panel closes on the
  second press.
- Shift+Tab skips a mode when the server refused the change before it.
- Handing a queued message to a turn wow started on Claude Code is read from the SDK's types, not
  seen from the real program; if it does not take it, the message waits for the turn to end.
- Files, pull requests and tickets in the chat side panel, diffs for edits, approvals with "always
  allow", and images in the composer are the next parts and are not in this release.
