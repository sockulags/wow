# wow 0.3.4

The third part of the agent workbench: reading a long conversation, subagents and background
work, a run review that keeps its gate in view, and an assistant that says what it did in words.

Built and reviewed by agents, run against mock agents and mock hosts only. Read "Known gaps".

## Changes

### Reading the conversation

- **A divider says when the model or mode changed** between turns, and each usage row names its
  model. A compaction shows as a divider with what triggered it.
- **The working line** reads "Running <command>" with the time and the number of tool calls, and
  tokens on Codex. The context meter turns amber when the context is nearly full and offers
  "Compact now" on Claude Code.
- **Rows show their times.** Reasoning reads "Thought for n s"; Ctrl+O opens or closes all of it.
- **Scrolled up during output,** "New output" shows and End goes back to the newest; End also
  works from the composer when the caret is at the end of the text. Alt+Up and Alt+Down move
  between messages and C copies one.
- **Ctrl+Shift+J goes to the next thing that needs you:** the oldest waiting approval, question,
  plan or gate, across threads and runs. A run that waits for checks is not counted.
- In the composer's skill list your own skills come first and wow's last.

### Subagents and background work

- **A subagent is one row** with its description, the number of tool calls and the time. Its own
  tool rows show nested while it runs and its answer after. A Codex agent call shows its prompt,
  state and final message.
- **Background work shows as chips** that count up; a chip opens to the last output Claude Code
  reported. Stop stops it. Ctrl+B sends a running command or subagent to the background.
- When Claude Code refuses a Stop or a Ctrl+B, the conversation says so and why.

### Reviewing a run

- **The gate bar stays at the top of the run view** and in view at 1024 px, also with the side
  panel laid over the view.
- **A waiting run is listed first** on the Runs tab.
- **C on a diff line takes a comment.** In a run the comments go into the send-back note as
  `path:line – text`, and Ctrl+Shift+Enter sends it back; in a chat's Changes they fill the
  composer.
- **Shift+Enter on a file opens it in your editor,** with the command from the new setting
  `viewer.editorCommand`. The assistant can only propose a change to that setting.
- A code block whose label is a path has "Open file".

### Assistant, calendar and plans

- **The assistant's conversation says what was done in words:** no raw tool row sits above a
  change, a proposal, a secret field or a question, and values read as on the settings page.
- **The assistant can propose an "always allow" rule** for a project. It is stored only on Yes,
  and never for a shell or a program that runs other programs.
- A waiting proposal shows above the assistant's composer.
- **The card form fits a 900 px window:** the footer stays in view and Ctrl+Enter saves. A
  refused save shows its reason beside the footer.
- **In a plan,** Enter on a file opens it rendered, and "Start a thread for this unit" opens a
  draft with the unit's contract, unsent.
- "Waiting for you" text is readable in the light theme.

### Fixed since 0.3.3

- A thread view asks for its link rules once per thread, and the answer reads no token.
- "Fixes: #123" is a chip again; `example.com:8080` is no longer a file link.
- "Edit queued message" puts the `@` files back as chips.
- An image pasted while a message is on its way stays with its thread when you switch away.
- "Always allow" offers no rule for `npx.cmd` and other `.cmd` names, nor for a runner behind
  options such as `pnpm --silent exec …`.
- A denied edit shows no "Open file".
- The provider's command list is kept for `providers.commandListSeconds` (30 seconds) instead of
  being asked each time the slash list opens.

## Known gaps

- Nothing in this release has been run against a real Claude Code or Codex, a real host, or on
  Windows outside CI. `docs/windows-smoke.md` has new lines for each part.
- Ctrl+B is also "Show or hide the sidebar". It sends work to the background only while a command
  or subagent runs, and toggles the sidebar otherwise. Ctrl+Enter saves a card and approves a
  gate; the card form takes the key while it is open. The keybindings page marks both pairs.
- A background shell command usually shows "Nothing reported yet": wow shows only what Claude
  Code reports about a task.
- With `viewer.editorShell` on, a command that puts `{path}` in quotes is refused; write `{path}`
  without quotes. A path with `%` is refused when cmd.exe reads the line.
- Over a run view below 1280 px the side panel is at most 464 px wide at 1024 px, its resize
  handle has a dead zone past that width, and in a window of 800 px or less the panel is narrower
  than its usual minimum.
- After a refused Stop following a failed turn, Retry and Resume sit on the refusal's row instead
  of the turn's own error.
- `pnpm add -D tsx` and `pnpm --filter web test` can still get an "always allow" rule (`pnpm add`,
  `pnpm`). The card shows the exact rule before you choose it.
- The key table in `docs/user-guide.md` lacks the new chat keys; they are described in the text.
- A comment on a removed diff line is not marked as removed in the note.
