# wow 0.5.0

Many threads at once: bring a thread's work home without a pull request, see every thread at
work in one list, keep a second thread open beside the one you are in, let a thread start helper
threads on Claude Code or Codex, and let a plan run deliver several units side by side. And see
more at a glance: a thread list that says where each thread stands, a summary per turn, plan
limits, usage, and more ways to put things into a message.

Built and reviewed by agents, run against mock agents and mock hosts only. Read "Known gaps".

## Changes

### Apply to project folder

- **"Apply to project folder…"** (**Ctrl+Shift+A**) in the Changes of a thread with its own
  working copy writes everything the thread changed since its copy was made, commits and
  uncommitted work alike, into the project's own folder as uncommitted changes.
- **Nothing of yours is overwritten.** A file you changed too is merged when Git can do it
  without a conflict; otherwise it stays as you have it, and the confirm says why (both changed
  the same lines, deleted on one side, a binary file, a link, too large).
- **A confirm lists every file** under Left for you, Merged, Written and Deleted. When the files
  change before you press Apply, it shows the new lists instead.
- **Undo** puts back each file Apply wrote or deleted, and names a file you changed since.
- Nothing is committed, staged or branched in either folder. Apply waits while a turn runs in the
  thread or in a thread that works in the project folder. The assistant cannot apply.

### Threads at work

- **At work** at the top of the thread list (**Ctrl+Shift+O**) lists the threads that wait for
  you, work, or finished a turn you have not read, with what each waits for, runs now ("Running
  pnpm test · 2:10 · 14 tool calls") or last said. Enter opens a thread; **P** opens it in the
  side panel.

### A thread beside another

- **Open thread in panel…** (**Ctrl+Alt+O**) opens any thread in a tab of the side panel next to
  the view you are in, with its conversation, cards and composer, and **Open thread**.

### Helper threads

- **Helper threads** (`chat.helpers`, per project, on by default) gives every chat thread's agent
  one more MCP server, `wow`, beside its own tools and servers, on Claude Code and Codex alike.
  Each thread has its own token, and nothing else opens it.
- With it the agent can **start a helper** on any connected instance, so a Claude thread can ask
  Codex and the other way round: in the same folder by default, or in its own working copy. The
  helper's mode is never wider than the main thread's, and its approvals are yours.
- **A helper's answer comes back** to the main thread as a message from wow, and so does its
  question, which the main thread's agent may answer. Approvals never.
- **You see them work.** The main thread shows each helper as a row with what it runs now, waits
  for or last said; it opens in the side panel. In the thread list and Threads at work a helper
  sits under its main thread. Stopping the main thread stops its helpers.
- The agent can also read how a helper stands, write to it and stop it. At most 3 helpers of one
  thread and 6 in all work at once (`chat.helpersPerThread`, `chat.helpersLive`).

### Units at once in a plan run

- **Units at once** (`workflows.planRunParallel`, per project, default 1) lets a plan run keep
  more than one unit's run going, each in its own working copy. The next ready unit starts when
  one ends. With the default nothing changes.
- With `workflows.planRunOnFailure` on `stop`, a failed unit starts nothing more and the plan run
  ends as failed once the other live runs have ended; with `skip` it goes on. Stop ends every live
  unit run.
- The plan run lists each live unit with the step its run is at and what that step's thread runs
  now, and Threads at work names the unit beside each step thread.

### Snapshots

- The first snapshot of a large folder reads its files several at a time
  (`chat.snapshotReadsAtOnce`), and every snapshot logs how many files it read and hashed and how
  long it took.
- A folder in daily use no longer reads and hashes every file again each time an old turn's
  snapshot is dropped after `chat.snapshotKeepDays` (#69).

### The thread list

- **Rows say where a thread stands**: what it waits for or runs, its task progress, what it
  changed and its branch or project (`chat.threadRowDetail` picks the parts).
- **Idle and Done are grouped** under Today, Yesterday, This week and Older; group headings fold
  and stay folded, Done starts folded, and **Group threads by project** groups by project
  instead. A done thread is archived after 14 days (`chat.doneArchiveDays`, 0 never).
- **Right-click a row** for its actions, hover for Pin and Archive, and **Ctrl+click, Space or
  Shift+click** to pick several rows; a bar then acts on all of them, and Archive offers Undo.

### The conversation

- **Each turn ends with what it did**: "Changed 3 files +40 −2 · Read 2 files, ran 1 command ·
  1 failed"; the changed files open that turn's Changes.
- **New since you looked**: a bold thread opens at a line before what you have not read
  (**Shift+End** goes there).
- **Outline and marks**: **Ctrl+Shift+U** lists your messages with what each turn did and the
  answers you marked; **B** marks a message, **Alt+PageUp/PageDown** moves between marks.
- **Pictures in tool rows**: a screenshot or an image a tool returned shows as a thumbnail.

### Limits, usage and messages

- **Plan limits**: Claude Code's 5-hour and weekly limits show in the composer bar from 80 %
  (`chat.limitWarnPercent`), in Settings → Providers, and as a notice once per window.
- **Usage** (foot of the thread list) shows tokens and cost per day, project, instance and model.
- **Text files** dropped or pasted on the composer go in as quoted blocks (up to 200 KB).
- **`@` another thread or a backlog item** puts its last answer or its text into the message;
  **issues, pull requests and tickets** too, for a project with **Issues and tickets in @** on,
  after a confirm each time and marked as written by others.

## Known gaps

- Nothing in this release has been run against a real Claude Code or Codex, a real GitHub or
  GitLab, a real Outlook, or on Windows outside CI. Apply's merge of a file with CRLF line endings
  on Windows is covered by tests on Linux only; a file whose two sides use different line endings
  is left for you.
- Two agents in one folder can write the same file at once, as Claude Code's subagents can; a
  helper that should not share asks for its own working copy.
- Two units at once double what runs on the machine and share the project's host account; that
  is why the default stays 1.
- That Codex keeps your own MCP servers from `config.toml` beside `wow` is read from its `-c`
  behaviour, not seen against a real codex. Turn **Helper threads** off for a project if your
  own servers go missing there.
- A turn running in another program (Claude Code in a terminal) in the project folder is not
  seen by Apply; the confirm's check for changes since covers what changed before Apply.
- Restore is still not offered for a step's thread, a folder outside Git, or messages from before
  0.3.9 (#69).
- Codex shows no plan limits: the protocol wow is built against has none. PDFs cannot go into a
  message yet, and a dropped file in the thread's folder does not become an `@` mention.
- The thread list's new rows, groups and menus, the outline, tool pictures, limits, usage and
  mentions are covered by unit tests; only archiving two picked threads has an end-to-end test.
- Open: #49, #65, #66 (Windows only), #67, #69.
