# wow 0.3.1

A chat that wakes up again when Claude's background agents finish, and fixes for what the reviews
of 0.3.0 left open.

Built and reviewed by agents, run against mock agents and mock hosts only. Read "Known gaps".

## Changes

### Background work

- **A turn Claude Code starts by itself is shown.** When Claude starts background agents, ends
  its turn to wait and then goes on when they finish, wow now shows that as a turn of its own:
  the thread runs, the answer streams in, Stop works, and the thread is marked when it ends.
  Before, nothing appeared until you wrote a message.
- **"Waiting for background work"** shows in the chat, with what is running, while no turn runs.
- **A workflow step waits for background agents** before it ends, so its gate and verdict are
  read from the last answer. It does not wait for background commands such as a dev server, and
  it ends when the agent ends without an answer or the provider is closed.

### Skills

- **Undo of a change or a delete of a skill restores the file exactly**, also a skill you wrote
  by hand with a name outside the name rule, an empty text or other frontmatter. A change in wow
  touches only the name, the description and the text.
- An Undo is refused when the file was edited by hand since the change.
- A skill's name and text can no longer close or forge the block the agent reads.
- Two skills of yours with the same name in different folders are both listed with their folder,
  and neither can be used until one is renamed.

### Chat, runs and wording

- The composer no longer rebuilds the command list on every keystroke.
- Retry in a workflow step's thread sends the step's message again as the step sent it.
- A run whose step waits for an answer says so in every list of runs.
- A GitLab project says "merge request" before wow has read from its host, also in refusals, the
  assistant's rows and the diagnosis.
- The assistant judges a repeating card by when it really fires next.

## Known gaps

- Nothing in this release has been run against a real Claude Code, Codex, GitHub Enterprise,
  GitLab, Jira, Confluence or Outlook, or on Windows outside CI.
- Which message a turn Claude Code starts by itself begins with was read from the SDK's types,
  not seen from a real Claude Code. Check the new line in `docs/windows-smoke.md` first: ask
  Claude to run a background agent and wait.
- If a background agent ends before its turn's result, wow has no signal that Claude will go on;
  such a workflow step ends with the first turn and the later turn only shows in the thread.
- While a thread only waits for background work, Stop has nothing to stop.
- Two skills of yours that share a name cannot be told apart in a workflow step or a message;
  rename one.
