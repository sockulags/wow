# wow 0.4.0

The assistant as a chief of staff: it reads what your agents did, keeps a queue of what waits for
you, briefs you, and, where you allow it, starts and follows work on its own.

Built and reviewed by agents, run against mock agents and mock hosts only. Read "Known gaps".

## Changes

### The assistant reads what your agents produced

- It reads a run's steps and their artifacts, a thread's last turns, and your free time in the
  calendar. It answers "what did the review say" from the work itself.
- **Memory.** "Remember: never plan anything before nine" becomes a note it follows from then on.
  Settings → Assistant → Memory lists every note with who wrote it, and you can add or remove
  them there.

### Standing permissions

- Settings → Assistant → Permissions: **Start threads**, **Start runs**, **Plan runs** and
  **Move cards**, each for the projects and workflows you pick. Each can end on a date, have a
  daily limit, or be paused. Nothing applies until "Let the assistant act under its
  permissions" (`assistant.delegation`) is on.
- Outside a permission the assistant still asks with a proposal, as before. Plans outside work
  hours always ask.
- **Focus cards** in the calendar are time kept free: the assistant plans nothing over them.

### Delegated work

- The assistant can start a thread in its own working copy, send it a message, and answer an
  agent's question from what you told it. The question card then says "Answered by the
  assistant · because you said …".
- It follows the threads and runs it started. When one ends or asks for something, it hears
  about it and reports back in its conversation. It never answers an approval or a gate.

### Needs you

- **The decision queue** sits beside the assistant's conversation. It lists approvals,
  questions, gates, limits, proposals, failed runs and missed cards, in the order they matter.
- Each item can have a short brief from the assistant with a recommendation. The answers are
  the same commands, with the same keys, as in the views they come from. The tray menu and
  "next that needs you" follow the same order.
- A failed run or missed card can be dismissed.

### Briefings, reminders and quiet

- With **Briefings** on (`assistant.briefings`): a briefing when work hours start, one when they
  end, and one when you come back after a while away. Each shows wow's own lines and, within
  `assistant.briefingsPerDay`, a summary by the assistant.
- A decision that has waited long gets one reminder.
- Notifications wait while you are in a meeting and come after it.
- When a meeting moves over a card with a workflow, the assistant proposes moving the card to
  the next free slot, or moves it under **Move cards**.

### Quick ask

- **Ctrl+Alt+Space** (`desktop.quickAskShortcut`) opens a small prompt on top of any program.
  Ask, see the answer stream, press Escape to hide it, or "Open in wow" for the conversation.
  When another program holds the key, a notification says so.

### Fixed since 0.3.10

- **Run ready units:** a plan run no longer starts the next unit from statuses the host gave
  before the last unit's run ended, which could start a unit someone else had claimed (#47).
- **Diagnosis:** a failed run or missed card you dismissed no longer counts as failing (#51).
- **Setup file:** steps that waited for a Claude Code or Codex instance are given the first one
  you add (#53).
- **Confluence:** a used-up request limit pauses only the token that used it, as GitHub and Jira
  already did (#58).
- **Commit from a thread** (#68):
  - A hook that stopped after the commit was made is shown under the commit line.
  - A file that changed after the dialog read it is refused instead of committed unseen.
  - A refused commit from a detached HEAD puts the folder back where it was.
  - Commit and pull request lines are found by Ctrl+F and are in the Markdown export.
- **Keybindings:** the table shows the Dialog and Approval scopes. Ctrl+Enter in the commit
  dialog and at a gate is no longer listed as a clash (#54).
- **Tests:** a thread list test and a tab test waited on timing (#62, #63); global keys are
  listened to before the first paint (#64); timers a web test leaves behind are cleared.

## Known gaps

- Nothing in this release has been run against a real Claude Code or Codex, a real GitHub or
  GitLab, a real Outlook, or on Windows outside CI.
- The assistant does not retry a failed run on its own: a provider failure and an agent's own
  failure cannot be told apart yet.
- Briefings use the assistant's own model; there is no separate model setting for them.
- A quick ask key that another program holds is reported in a notification, not in Settings.
- Open: #49 (Codex without a real binary), #65, #66 (Windows only), #67 (worktree upkeep; see
  `intents/2026-11-unattended-runs`), #69.
