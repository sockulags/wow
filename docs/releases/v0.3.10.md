# wow 0.3.10

Commit a thread's changes and open a pull request from the thread.

Built and reviewed by agents, run against mock agents and mock hosts only. Read "Known gaps".

## Changes

### Commit from a thread's Changes

- **"Commit…" in a chat thread's Changes** lists every changed and new file. The files the
  thread changed are ticked; a file you changed yourself is not. Whole files only.
- **Your hooks run,** on your click. The dialog names the commit hooks it found. A hook that
  refuses shows its output and nothing is committed. wow never passes `--no-verify`.
- **"Propose" asks the agent for a message** from the diff of the ticked files. It runs outside
  the conversation, with no tools, and the thread stays as it was. Cancel stops it.
- Only the ticked files go into the commit; what you had staged stays staged. The thread shows
  a line with the sha and the subject.
- An empty message, a running turn and a rebase in progress are refused. From a detached HEAD
  the commit needs a new branch name and is made on it.

### Open a pull request

- **"Open pull request…"** shows the target branch, the commits, a title and a body. Open pushes
  the branch with its upstream set and opens the request on GitHub or GitLab (a merge request,
  as a draft when `chat.pullRequestDraft` is on). The thread shows "Opened pull request #n" with
  a chip that opens it in the panel.
- **Refused before anything is pushed:** no token, a protected branch, the remote's default
  branch, the target as the branch, or no commit ahead. The reason names the setting or fact.
- **Push uses Git's own credentials and never waits for a prompt.** When Git would ask, the push
  fails at once and says to push once in a terminal. The host token goes only in the request to
  the host, never in a git argument or environment.
- When the host refuses, its message shows, the branch stays pushed and Open works again. With a
  request already open, the dialog offers "Open in panel" and "Push the new commits".

### Limits that hold

- No amend, merge, rebase, pull or force push, and wow never deletes a branch.
- Chat threads only. The assistant and workflow steps have no way to commit, push, open a
  request or ask for a proposal.

### Fixed since 0.3.9

- An e2e test of the meeting panel failed on Saturdays and Sundays.

## Known gaps

- Nothing in this release has been run against a real Claude Code or Codex, a real GitHub or
  GitLab, or on Windows outside CI. Hooks that need programs such as `sh` on Windows, and a push
  with a real credential helper, are not tried.
- When a hook stops after the commit was made, the commit is recorded, but the dialog does not
  show the note that the hook did not finish; it is in the log.
- A file changed between the dialog and Commit is committed as it is on disk.
- A commit refused after a detached HEAD got its new branch leaves the folder on that branch;
  the refusal names it.
- Whether a Codex proposal can see MCP servers from the user's own `config.toml` is not
  verified.
- Commit and pull request lines are not in Ctrl+F or the Markdown export.
- `keybindings.commitConfirm` and the gate's approve key are both Ctrl+Enter by default. They
  apply in different places; Settings lists them as a clash.
