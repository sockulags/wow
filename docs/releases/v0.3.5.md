# wow 0.3.5

The last part of the agent workbench: edit the last message, fork a thread, open a session you
started in a terminal, and a round of small polish.

Built and reviewed by agents, run against mock agents and mock hosts only. Read "Known gaps".

## Changes

### Edit and fork (Claude Code)

- **Up in an empty composer loads your last message.** Sent again, the conversation goes on from
  before it, and "Earlier version" shows the exchange it replaced. E on the last message does the
  same. The composer says when the replaced turn changed files: files stay as they are.
- **"Fork from here"** on a message, or F, opens a new thread that holds the conversation up to
  that message, with the same model, mode and folder, and a link back to where it came from. The
  images of the messages it keeps are copied to it.
- When Claude Code refuses to go back, the error row offers "Go on without going back", or
  "Start a new conversation" in a fork.
- On Codex neither is offered, and their palette commands say why.

### Sessions from the terminal

- **"Open session from Claude Code / Codex…"** in the palette lists the sessions found in each
  instance's files, by folder, with the first prompt and the time. Picking one opens a thread that
  resumes it. A session a wow thread already goes on with is shown as that thread, and a second
  thread on it is refused.
- `providers.sessionListLimit` sets how many are listed.

### Small polish

- **Models read by their label** in the builder, on a run and in the Assistant header, with the id
  in a tooltip.
- **Ctrl+4 opens Plans and Ctrl+5 Backlog.** The palette's input stays where it is as the results
  shrink.
- **The send key can be Ctrl+Enter;** Enter then makes a new line.
- **A project can have a default model, effort and mode** for new threads.
- A card waiting at its gate reads "Waiting for you". Diagram labels have no grey box.

### Fixed since 0.3.4

- After a refused Stop that follows a failed turn, Retry and Resume stay on the turn's own error.
- Over a run view the panel's resize handle starts from the width shown and stores no more than
  that; a click on the edge without a drag changes nothing; the panel is never narrower than its
  minimum.
- A comment on a removed diff line is marked "(removed)" in the note.
- The key table in the user guide has the chat keys.
- A session's first prompt is your prompt, not Codex's instructions note or an IDE's context.

## Known gaps

- Nothing in this release has been run against a real Claude Code or Codex, a real host, or on
  Windows outside CI. `docs/windows-smoke.md` has new lines for each part.
- Edit and Fork rest on how Claude Code resumes a session at a message, read from the SDK's types
  and not seen from the real program. If it refuses, use "Go on without going back"; the agent
  then still remembers the exchange wow shows as replaced.
- Which lines of a session file are Claude Code's own notes is a list written from memory, not
  checked against a real session folder. A note it misses shows as the session's first prompt.
- Edit and Fork are offered in chat threads only, not in a workflow step's thread. A fork's title
  can be longer than `chat.threadTitleMaxLength`.
- In CI on Windows something kept a project folder held while wow ran, so the folder could not be
  removed. The cause is not found. Removing or moving a project's folder while wow runs may fail
  there until wow is closed.
- 800 px is the narrowest window laid out for, the desktop window's own minimum.
- The keybindings page marks four pairs of defaults that share a key: Ctrl+B (to background and
  the sidebar), Ctrl+Enter (save a card and approve a gate), D (day view and deny), and
  Ctrl+Shift+D (a run's and a thread's Changes). Each acts where its view has the keyboard.
