# wow 0.3.6

A small release about Git on Windows, on the way to finding what kept a project folder held in
0.3.4 and 0.3.5.

Built and reviewed by agents, run against mock agents and mock hosts only. Read "Known gaps".

## Changes

- **A git that wow stops is stopped whole on Windows.** `git` on the PATH there is a small
  program that starts the real one. When a git command ran out of time, wow stopped only the
  small one, and the real git could stay running in the project's folder. wow now stops both and
  waits for them to be gone before it answers.
- **The wait has an end.** `advanced.gitStopWaitMs` (5 seconds) is how long wow waits for a
  stopped git; after that it answers with what it has. The file list does the same at its limit
  and when it runs out of time.
- A plan for the next part, work on a thread once the agent has changed files, is in
  `intents/2026-11-thread-work`. Nothing of it is built in this release.

## Known gaps

- Nothing in this release has been run against a real Claude Code or Codex, a real host, or on
  Windows outside CI.
- Whether the git left running was what kept a project folder held is not proven. The end-to-end
  tests now write down which programs hold a folder they cannot move, so a run on Windows can
  name the holder. Until one does, removing or moving a project's folder while wow runs may
  still fail there.
- The other gaps of 0.3.5 stand; see `docs/releases/v0.3.5.md`.
