# wow 0.3.3

The second part of the agent workbench: files, pull requests and tickets open in tabs beside the
chat, edits show as diffs you approve, a thread lists what it changed, and the composer takes
images.

Built and reviewed by agents, run against mock agents and mock hosts only. Read "Known gaps".

## Changes

### Files and tabs beside the chat

- **The side panel has tabs,** in chat as in a run. A file path in a message is a link that opens
  the file in a tab; `src/timer.ts:42` and `docs/spec.md#rules` open the file itself. Markdown is
  shown rendered, code with highlighting.
- **"Open file…"** in the palette lists the thread's files. `@` in the composer does the same and
  sends the file with the message as a chip. A queued message keeps its files.
- **A Read row has Open,** which opens the file it read.
- Each thread, run and calendar card keeps its own tabs. One file is one tab however its path is
  written.

### Pull requests, issues, tickets and pages in chat

- **A link to a GitHub or GitLab pull request or issue, a Jira ticket or a Confluence page** on a
  host wow has settings for is shown as a chip with its key and state, and opens in a tab with its
  text, state and checks. "Refresh now" reads it again.
- A bare `#12` or `ABC-123` is a chip when it matches the project's repository or tracker. Text
  in inline code and colour codes are left alone.
- **"Mentioned"** in the thread's details lists the files and links of the thread.

### Diffs, changes and approvals

- **An edit is shown as a diff,** in its tool row and in the approval card, with the lines added
  and removed. "Open file" opens the file in a tab once the edit is made.
- **The approval card says what is asked in wow's words** and can be answered with keys: allow,
  deny, deny with a note to the agent, or always allow.
- **"Always allow"** stores a rule for the project, shown before you choose it, for a command's
  first words or a tool. No rule is offered for an edit, a shell, a program that runs another
  program, or a command with quotes. The rules are listed in Settings and can be removed. The
  assistant can only propose a rule.
- **A plan the agent asks to start from** is shown as a card to approve or send back with a note.
- **Changes** is a tab that lists what the thread changed since it started, or in the last turn
  only, with each file's diff. Ctrl+Shift+D opens it.

### Images in the composer

- **Paste or drop a PNG, JPEG, GIF or WebP** into the composer of a chat thread. It shows as a
  chip, goes with the message to Claude Code or Codex, and stays with the thread after a restart.
- wow says why when it takes no image: too large, a kind it does not take, or a model without
  image input. The assistant and workflow steps take no images.

### Fixed since 0.3.2

- Escape in a workflow step's composer closes the side panel on the first press.
- Shift+Tab no longer skips a mode after a refused change.
- The slash list shows a project command added while the app is open.

## Known gaps

- Nothing in this release has been run against a real Claude Code or Codex, a real GitHub, GitLab,
  Jira or Confluence, or on Windows outside CI. `docs/windows-smoke.md` has new lines for all four
  parts.
- How Codex reports a command inside a shell line on Windows is read from its protocol, not seen.
  If the approval card shows the whole shell line, no rule is offered and wow asks every time.
- The guard against rules for programs that run other programs can be stepped around with a
  `.cmd` name (`npx.cmd`) or an option before the sub-command (`pnpm --silent exec …`). The card
  always shows the exact rule before you choose it.
- "Fixes: #123" is read as a colour and gets no chip. `example.com:8080` in a message is read as
  a file link.
- "Edit queued message" puts back the text and images but not the `@` files.
- An image pasted while a message is on its way is lost if you switch thread before the send
  answers. Stored images are not deleted with their thread.
- A code block whose label is a path has no "Open file" yet.
- A database that ran an unreleased build of this work may fail to start; start from a fresh
  `~/.wow` in that case. Homes from 0.3.2 and earlier update as usual.
