# wow 0.3.0

Cards that repeat, questions you answer with a click, an assistant that knows the models, wow's
own skills, and fixes for what the reviews of 0.2.0 left open.

Everything here was built and reviewed by agents and has only been run against mock agents and
mock hosts, apart from the owner's first use of the assistant on Claude Code. Read "Known gaps"
before relying on it.

## Changes

### Cards that repeat

- **A card can repeat:** every day, on chosen weekdays, every week or every month, with an
  interval, ending never, on a date or after a number of times. The card's editor has a Repeat
  section that says the rule in words and when it fires next.
- **One card, one schedule.** Changing it changes the days that have not started; days that have
  passed stay where they were. Delete asks "This occurrence" or "The whole series". One Undo puts
  either back.
- **The clock time holds** across daylight saving changes.
- **No pile-up.** After the app was closed over several occurrences only the latest follows the
  missed-trigger setting. An occurrence whose earlier run is still going is skipped with a notice.
- **The assistant makes one repeating card** when asked for something recurring.

### Questions

- **One question card everywhere:** in the assistant, in chat threads and in workflow steps. A
  header, choices with the recommended one first, "Other" for your own text, several picks where
  allowed, and several questions answered together. Arrows or digits pick, Enter sends.
- **The assistant asks with it.** It is refused when the question asks for a token or password
  and told to show the secret field.

### Models

- **The assistant reads the models and efforts each connected provider offers** and wow's guidance
  on which kind suits planning, building, reviewing and mechanical steps. The guidance is a
  setting you can edit.
- **Every step the assistant writes names a model and an effort the provider offers**, and it says
  why. A model the provider does not offer, or a provider that is not connected, is refused.
- **A Codex step needs a model.** Saved without one it takes the instance's default; without a
  default it is refused, in the builder, from the assistant and from a setup file alike.

### Skills

- **wow's own skills:** `wow-verdict`, `wow-artifacts`, `wow-pull-request` and `wow-handover`, in a
  group "wow" in every skill list. They tell the agent what only wow knows, are filled in from
  your settings, and work the same on Claude Code and Codex.
- **Attached where the workflow needs them:** a step whose gate or rule reads the verdict gets
  `wow-verdict`, a step with expected artifacts gets `wow-artifacts`. The builder shows it and
  lets you leave one out.
- **Your skills:** write, change and remove skills under Settings → Skills. They are listed first,
  as "Yours", and travel in the setup file.
- **Also follow:** a step can be given more skills beside the one it runs.
- **Pick a skill with `/`.** A picked skill is a chip in the composer and in the sent message.
  `$` no longer opens the list; the character is the setting `chat.skillTrigger`.
- The assistant can propose a skill of yours; it always waits for your yes and shows the text.

### Chat

- **Tool calls take one row:** a run of tool calls in a turn shows the latest call and a count,
  and opens to all of them. A failed call shows without opening. Setting `chat.groupToolCalls`.

### Assistant on Codex

- On Codex, wow now switches off Codex's shell and the other built-in tools that have a switch
  for the assistant's thread, and your own MCP servers are not loaded for it. "Let the assistant
  run on Codex" is still off by default, because nobody has seen the resulting tool list with a
  signed-in Codex.

### Automation and hosts

- **Pull requests from forks start nothing** unless `triggers.forkPullRequests` is turned on for
  the project; a notice says why. A run for an event on an open pull request starts at its head
  commit; a merged event starts at the default branch.
- A rule that reruns a step waits for the thread's turn instead of failing the run. The server
  says whether a wait is before or after a step. "This step" marks follow the right step after a
  loop.
- Jira markup is turned into markdown in linear time. A host's request limit can no longer park
  polling for longer than a setting allows. GitLab projects say "merge request". Projects on
  `<name>.ghe.com` call the right API host. Confluence pages are bounded in size and only stored
  when they change.
- The assistant's diagnosis forgets failures of deleted workflows and projects. The first-start
  greeting survives a reload. A setup file's "to fill in" list is walked after applying it from
  Settings.

## Known gaps

- Nothing in this release has been run against a real Codex, a real GitHub Enterprise, GitLab,
  Jira or Confluence, a real Outlook, or on Windows outside CI.
- Whether Codex takes typed text as the answer to a question that has choices is fixed only in
  adapter tests; check it with the real provider.
- Moving a single occurrence of a repeating card moves the series from that day on. Schedules
  finer than a day are not possible.
- A GitLab project wow has not read yet is worded as GitHub until its first read.
- Deleting a skill you wrote by hand in wow's skills folder cannot always be undone exactly: a
  name outside the name rule, an empty text or extra frontmatter is not restored.
- The composer registers itself again on every keystroke, which rebuilds the command list more
  often than needed.
